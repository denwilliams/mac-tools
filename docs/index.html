Mac Tools: Island

A thin colour strip across the top of your screen that drops down to show what just happened, then gets out of the way. Anything can push to it: Claude Code sessions, your Slack harness, CI jobs, scripts, or cloud services.

How to push to itThe CLI

How it works

Island is one app in a suite of Mac tools. It lives in the menu bar and draws over the top edge of every display. Native Swift and SwiftUI, no Electron.

1. Ambient strip

A 3px strip sits beside the clock. It's invisible when idle and goes colour when something happens: one segment per activity, filled by progress, pulsing while running or waiting.

2. Auto drop-down

When a new message arrives the island drops down for about five seconds to show the content, then retracts. Mark an event quiet to skip this.

3. Hover to interact

Rest the cursor on the top edge for a moment and the island opens. Click a row to open its link, or dismiss it with the x. It closes shortly after you leave.

4. Every display

One click-through window per screen, so it works on a notched MacBook, an external monitor, or both. The strip never blocks the menu bar.

Status colours

info running (pulses, up to 30 min) waiting (pulses fast, up to 1 hr) success (10 s) warning (10 s) error (pulses, 30 s)

Times in brackets are how long an event stays if its sender never updates or clears it. Override with ttl.

Pushing content

Four ways in, one event format. Pick whichever your sender can do.

Event fields

FieldNotes
titleRequired.
idUpsert key. Reuse it to update a row instead of adding a new one. Generated if omitted.
subtitle, sourceSecond line, and a small tag (for example claude or slack).
statusinfo · running · waiting · success · warning · error. Sets the colour.
progress0 to 1. Fills the strip segment.
iconAn SF Symbol name.
urlOpened when the row is clicked.
ttlSeconds before it disappears.
quiet, soundDon't drop the island down on arrival; play a sound.

1. HTTP

The app listens on 127.0.0.1:7878, loopback only. Send an object or an array.

# add or update
curl -X POST 127.0.0.1:7878/v1/events \
  -H 'content-type: application/json' \
  -d '{"id":"deploy","title":"Deploying","status":"running","progress":0.4}'

# remove one / remove all
curl -X DELETE 127.0.0.1:7878/v1/events/deploy
curl -X POST   127.0.0.1:7878/v1/clear

Use 127.0.0.1, not localhost. The content-type: application/json header is required, and requests carrying an Origin header are rejected, so a web page in your browser can't push to it.

2. Node

import { push } from './tools/notch-push.mjs';
await push({ id: 'deploy', title: 'Deploying', status: 'running', progress: 0.4 });
await push({ op: 'clear', id: 'deploy' });

3. Drop a file

Write a .json file (one event or an array) into ~/.mactools/inbox/. It's picked up within half a second and deleted. Good for scripts that can't make HTTP calls.

The notch CLI

A single zero-dependency Node script. Symlink tools/notch.mjs onto your PATH as notch.

notch "Deploying" "prod" -s running -p 40 -i deploy   # title, subtitle, flags
notch "Deploy done" -s success -i deploy --sound      # same id updates the row
notch run --title "Tests" -- npm test                 # wrap a command
long_job | notch json                                 # event JSON from stdin
notch clear deploy                                    # one row; `notch clear` = all
notch ping                                            # is the island running?

notch run is the useful one. It shows your command as running, then flips to success with the time taken ("Done in 2m 14s") or error with the exit code. Output passes through and the exit code is preserved, so it's safe in scripts and && chains. If the island isn't running, your command still runs.

Flags: -i id, -s status, -p progress (0–1 or 0–100), -u url, -t title, --source, --icon, --ttl, --quiet, --sound. Set NOTCH_URL to point at a different address.

Claude Code sessions

tools/claude-hook.mjs turns Claude Code hook events into one row per session, labelled with the project folder.

HookShows
UserPromptSubmitRunning, with the start of your prompt
PreToolUseRunning, with the tool name
NotificationWaiting (yellow, with sound): Claude needs you
StopDone (green, with sound)
SessionEndRow removed

Add to ~/.claude/settings.json, repeating the same command block for each hook name above:

{
  "hooks": {
    "Stop": [
      { "hooks": [ { "type": "command",
          "command": "node /path/to/mac-tools/tools/claude-hook.mjs" } ] }
    ]
  }
}

The hook never blocks Claude: if the island isn't running it exits quietly.

Cloud push

Cloud systems can't reach your Mac directly, so you host a tiny relay. They POST to it; your Mac holds a connection to its stream and shows what arrives.

# 1. run the relay anywhere that runs Node (behind HTTPS)
PUSH_TOKEN=... STREAM_TOKEN=... node relay/server.mjs

# 2. cloud systems push
curl -X POST https://your-host/push \
  -H 'Authorization: Bearer $PUSH_TOKEN' -H 'content-type: application/json' \
  -d '{"title":"Alert","status":"error","source":"prod"}'

# 3. ~/.mactools/config.json on your Mac
{ "relay": { "url": "https://your-host/stream", "token": "..." } }

The Mac reconnects automatically with backoff, and the relay replays its last 20 events to a reconnecting client. Use two different tokens: one for senders, one for your Mac.
